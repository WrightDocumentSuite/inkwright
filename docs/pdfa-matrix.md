# Матрица соответствия ISO 19005 (PDF/A)

Построчная сверка библиотеки с нормативными текстами трёх частей стандарта. Источник — купленные
тексты в `DOCS/FULLSPEC`: ISO 19005-1:2005 с поправками Cor.1:2007 и Cor.2:2011, ISO 19005-2:2011,
ISO 19005-3:2012.

Столбцы «часть 1» и «часть 2/3» — номера пунктов; там, где части расходятся по существу, различие
описано в строке. Часть 3 повторяет часть 2 за исключением §6.8, поэтому отдельный столбец ей не
нужен.

Обозначения в столбце «состояние»:

| Знак | Смысл |
| --- | --- |
| Г | генератор гарантирует: то, что пишет библиотека, требование не нарушает |
| В | валидатор проверяет: нарушение в чужом или правленом файле будет найдено |
| ГВ | и то, и другое |
| — | не проверяется; в строке сказано, почему |
| н/п | не применимо к тому, что библиотека умеет создавать |

Правила живут в `src/Inkwright.Layout/PdfA/`, по файлу на раздел стандарта; каждая находка
называет пункт, который нарушен. Матрица проверена двумя способами: библиотека валидирует
собственный вывод на всех восьми уровнях, и валидатор принимает 106 архивных файлов из тестового
набора iText, которые заявляют части 1–3.

## Что заведомо не проверяется

Эти требования нельзя проверить из файла, и валидатор о них молчит намеренно, а не по забывчивости:

- законность встраивания шрифта (6.3.4 / 6.2.11.4.1) — вопрос лицензии, а не байтов;
- соответствие вложенного PDF своей части стандарта (6.8) — потребовало бы рекурсивной проверки
  вложения как отдельного документа;
- ограничения кодового потока JPEG 2000 (6.2.8.3) — библиотека не разбирает JPX;
- согласие `CIDSystemInfo` шрифта с предопределённой CMap (6.2.11.3.1) — нужны таблицы Adobe;
- `ActualText` для символов из области частного использования (6.2.11.7.3);
- исключение для шрифтов, которыми рисуют только невидимый текст (режим 3): валидатор требует
  встраивания для всех шрифтов, что строже стандарта, но безопаснее для архива;
- сверка `Widths` простых (не композитных) шрифтов с программой — библиотека простых шрифтов не
  пишет, а чужие файлы этой проверки не получают;
- разделение слов пробелами в строках показа (6.7.3.2) — надёжной автоматической проверки нет;
- рекомендации («should»): `xmpMM:History`, метаданные шрифтов, `Alt`, `E`, описания нетекстовых
  аннотаций;
- требования к поведению читателя, а не к файлу: показ `Contents` аннотаций, обработка `GoToR`,
  `URI` и `SubmitForm`, игнорирование `FL`, `Trans` и `Dur`.

Полную формальную проверку по-прежнему стоит делать veraPDF; эта матрица говорит, где библиотека
даёт гарантию сама и где полагается на внешний валидатор.
