# Чтение и правка

## Открытие

```csharp
using PdfDocument document = PdfDocument.Load("input.pdf");
using PdfDocument fromBytes = PdfDocument.Load(bytes);
using PdfDocument fromStream = PdfDocument.Load(stream);
using PdfDocument async = await PdfDocument.LoadAsync("input.pdf");
```

`PdfReader` доступен и сам по себе, если нужен слой ниже модели: он отдаёт трейлер, каталог и любой
объект по номеру, не строя дерево страниц.

```csharp
using Inkwright.IO;

PdfReader reader = PdfReader.Open(bytes);
PdfValue root = reader.Resolve(reader.Trailer[PdfName.Get("Root")]);
```

## Диагностика вместо тихих отказов

Всё, что читатель сумел обойти, попадает в `LoadDiagnostics` с кодом и адресом:

```csharp
var options = new PdfReadOptions
{
    Password = "secret",
    Recover = true,                            // по умолчанию
    OnWarning = warning => log.Warning("{Warning}", warning),
};

using PdfDocument document = PdfDocument.Load(path, options);

if (document.Diagnostics.Contains(PdfWarningCode.XrefRebuilt))
    log.Warning("Таблица ссылок собрана заново");
```

Коды перечислены в `PdfWarningCode`: от `HeaderNotAtStart` и `StreamLengthMismatch` до
`PageTreeRecovered` и `DecryptionSuspect`. Единственное исключение, которое библиотека бросает при
чтении, — `PdfFormatException`, и только когда в данных нет ни заголовка, ни объектов.

На текущем корпусе из 7807 файлов читаются 7800; пять отвергнутых — намеренно повреждённые
фуззинг-фикстуры без каталога, заголовка или читаемых объектов, ещё два файла пусты и не передаются
парсеру. Для всех документов, допущенных политикой теста до перезаписи, round-trip завершается без
отказов и сохраняет число страниц.

## Шифрование

Чтение поддерживает стандартный обработчик ревизий 2–7: RC4-40 и RC4-128, AES-128, AES-256 в обеих
версиях и AES-GCM из PDF 2.0. На корпусе открываются файлы всех этих разновидностей.
Потоковый ключ выбирается не только по `/StmF`: явный фильтр `/Crypt` учитывает своё
`/DecodeParms /Name` (включая `/Identity`), а потоки `/EmbeddedFile` без явного фильтра используют
`/EFF`. Это важно для файлов, где зашифрованы только вложения, а страницы оставлены открытыми.

```csharp
using PdfDocument document = PdfDocument.Load(path, new PdfReadOptions { Password = "owner" });

if (document.WasEncrypted)
    Console.WriteLine($"Разрешено: {document.SourcePermissions}");
```

Пароль, который не подошёл, бросает `PdfPasswordException`. Это принципиально: без пароля документ
разбирается структурно, но каждая строка и каждый поток в нём — шифротекст, то есть файл выглядит
как документ без текста. Тот, кто прогоняет пакет файлов, получил бы пустые результаты и не узнал бы
об этом. Свойство `WasPasswordSupplied` отличает «пароль нужен» от «пароль неверный».

Инструменту, который только сортирует файлы по признаку «заперт или нет», исключение мешает:

```csharp
using PdfDocument document = PdfDocument.Load(path, new PdfReadOptions { OpenLockedDocuments = true });

if (document.WasEncrypted && document.Diagnostics.Contains(PdfWarningCode.UnsupportedSecurityHandler))
    Console.WriteLine("Заперт; содержимое читать нельзя");
```

Сертификатные обработчики (`/Adobe.PubSec`) открываются через сертификат с закрытым ключом; пример
приведён ниже.

Запись шифрует AES-256:

```csharp
document.Save("secret.pdf", new PdfSaveOptions
{
    Encryption = new PdfEncryptionSettings
    {
        UserPassword = "open-me",
        OwnerPassword = "owner",
        Permissions = PdfPermissions.Print | PdfPermissions.ExtractForAccessibility,
        EncryptMetadata = false,     // XMP останется читаемым для индексаторов
    },
});
```

Сохранение загруженного зашифрованного документа без `Encryption` снимает защиту, а с новыми
настройками — перешифровывает свежим ключом. Инкрементальное сохранение переиспользует ключ
исходного файла, поэтому дописывать в зашифрованный документ можно.

### Режим Галуа со счётчиком

По умолчанию шифрование идёт в режиме сцепления блоков — версия 5, ревизия 6, метод `AESV3`. Это то,
что откроет любая читалка. ISO/TS 32003 добавляет режим Галуа со счётчиком: версия 6, ревизия 7,
метод `AESV4`.

```csharp
Encryption = new PdfEncryptionSettings
{
    UserPassword = "open-me",
    UseGaloisCounterMode = true,
}
```

Разница по существу одна, и она важная: обычное шифрование только скрывает содержимое, ничего не
говоря о его подлинности. Расшифровав файл успешно, читатель не узнал ровным счётом ничего о том,
те ли это байты, которые записал автор. Режим Галуа со счётчиком считает поверх шифротекста тег
аутентификации, и изменённый файл не расшифровывается вовсе, вместо того чтобы расшифроваться во
что-то правдоподобное и неверное.

Отсюда поведение при чтении: несовпадение тега поднимает `PdfTamperedException`, а не возвращает
пустоту. Потоки расшифровываются по мере обращения, поэтому исключение прилетит либо при загрузке —
если испорчены данные перекрёстных ссылок, — либо при первом обращении к содержимому. Выбрать
аутентифицированный шифр — это и значит попросить, чтобы об этом сказали.

Цена — совместимость: читалка старше технической спецификации такой файл не откроет вообще. Поэтому
умолчание осталось прежним. При включении режима в словарь расширений каталога пишется объявление
ISO/TS 32003 по ISO 32000-2 §7.12.

### Сертификатное шифрование

Вместо пароля документ можно зашифровать на держателей именованных сертификатов X.509 (§7.6.5): ключ
файла заворачивается для каждого получателя в конверт CMS, и разворачивает его только чей-то закрытый
ключ. Всё построено на `EnvelopedCms` из базовой библиотеки — ни BouncyCastle, ни нативных
зависимостей.

```csharp
// Запись: зашифровать для двух получателей
byte[] file = document.ToArray(new PdfSaveOptions
{
    Encryption = new PdfEncryptionSettings { Recipients = [aliceCertificate, bobCertificate] },
});

// Чтение: открыть своим сертификатом с закрытым ключом
using PdfDocument opened = PdfDocument.Load(file, new PdfReadOptions
{
    DecryptionCertificate = aliceCertificate,
});
```

Пишется 256-битный AES с крипто-фильтрами (`adbe.pkcs7.s5`, `Adobe.PubSec`), ключ файла выводится из
двадцатибайтовой затравки и байтов конвертов получателей, как велит §7.6.5.3. Сертификат, для которого
документ не шифровали, его не откроет; с включённым восстановлением это `PdfPasswordException`, а не
тихая гора шифротекста.

### Защита целостности

ISO/TS 32004 описывает отдельный механизм — код аутентификации сообщения, привязанный к ключу
шифрования файла. Он отвечает на вопрос, на который шифрование не отвечает: успешная расшифровка
не говорит ровно ничего о том, те ли это байты, которые записал автор. Правильный код говорит, что
тот, кто его поставил, знал пароль.

Записать:

```csharp
document.Save("sealed.pdf", new PdfSaveOptions
{
    AddIntegrityCode = true,
    Encryption = new PdfEncryptionSettings { UserPassword = "open-me" },
});
```

Проверить:

```csharp
PdfMacIntegrity integrity = PdfMacIntegrity.Read(document);

if (integrity.IsVerified)
    Console.WriteLine("Файл цел и подлинен");
else if (integrity.IsPresent)
    Console.WriteLine(integrity.VerificationNote);
else if (integrity.IsRequired)
    Console.WriteLine("Обязательный AuthCode удалён");
```

Проверок две, и они отвечают на разные вопросы. `IsAuthentic` — HMAC выведен из ключа шифрования
этого документа, то есть атрибуты токена настоящие. `MatchesContent` требует всю цепочку привязки:
`messageDigest` аутентифицированных атрибутов совпадает с payload, `dataDigest` — с покрытыми байтами,
а у токена подписи `signatureDigest` — с необработанным значением подписи. Токен может быть настоящим
и при этом устаревшим: так бывает, когда документ инкрементально обновили и не пересчитали код.

Цепочка целиком: HKDF-SHA256 от ключа файла с солью `KDFSalt` и меткой `PDFMAC` даёт ключ обёртки;
им по RFC 3394 разворачивается ключ кода; HMAC-SHA256 над аутентифицированными атрибутами CMS
сверяется с записанным, после чего обязательный `messageDigest` связывает эти атрибуты с payload.
Проверено на 94 файлах тестового набора iText, включая SHA-2 и доступные системе SHA-3 варианты.

Соль по стандарту одна на всю жизнь документа, поэтому её пишет только `AddIntegrityCode` при
шифровании. Подписать документ с кодом можно (см. [signing.md](signing.md)), но соль должна быть
проставлена заранее: словарь шифрования — единственный объект, который пишется открытым текстом, и
переписать его в инкрементальном обновлении нельзя.

Тринадцатый бит разрешений при этом обнуляется. У парольного обработчика одинаковое значение
записывается в открытый `P` и зашифрованный `Perms`; у сертификатного — внутрь CMS-конверта
получателя. Читатель сверяет защищённое и открытое значения и сообщает `IsRequired`, даже если
злоумышленник полностью удалил `AuthCode`.

Разрешения библиотека сообщает, но не применяет: запрет на печать или копирование — это указание
читателю, а не замок. Код, который обязан их соблюдать, должен проверить `SourcePermissions` сам.

## Страницы

```csharp
PdfPage page = document.Pages[0];

page.Rotation = 90;
page.CropBox = page.MediaBox.Deflate(20);

document.Pages.Move(0, 3);
document.Pages.RemoveAt(1);
document.Pages.Insert(0, PageSize.A4.Landscape);
```

Импорт из другого документа тянет за собой всё, до чего страница дотягивается, и копирует общие
объекты один раз:

```csharp
using PdfDocument source = PdfDocument.Load("appendix.pdf");
document.Pages.ImportAll(source);
```

Закладки, назначения, поля и структура при этом тоже переезжают — подробности в
[merging.md](merging.md).

## Как называются страницы

Номер страницы и её имя — разные вещи. Документ, у которого предисловие идёт i, ii, iii, а основная
часть начинается заново с единицы, говорит об этом здесь; просмотрщик, показывающий «страница 3 из
40», показывает именно это, а не индекс.

```csharp
IReadOnlyList<string> labels = document.PageLabels.All();   // ["i", "ii", "iii", "1", "2", ...]
string third = document.PageLabels[2];

document.PageLabels.Set(
[
    new PageLabelRange(0, PageLabelStyle.LowercaseRoman),
    new PageLabelRange(3, PageLabelStyle.Decimal, prefix: "A-", start: 1),
]);
```

Дерево обязано начинаться с диапазона для нулевой страницы (§12.4.2); если вызывающий его не дал,
он добавляется сам. Буквы считаются A…Z, потом AA…ZZ, потом AAA…ZZZ.

## Слои

```csharp
foreach (PdfLayer layer in document.OptionalContent.Layers)
    Console.WriteLine($"{layer.Name}: {(layer.IsVisible ? "показан" : "скрыт")}");
```

Слои держат то, что страница рисует, но не всегда собирается показывать: варианты чертежа на другом
языке, водяной знак только для печати. Извлечение текста может их пропускать —
`TextExtractionOptions.SkipHiddenLayers`.

Учитываются не только состояния ON и OFF, но и политика словаря принадлежности `/P` (AllOn, AnyOn,
AnyOff, AllOff) и выражения видимости `/VE` с вложенными `/And`, `/Or` и `/Not`.

## Фильтры

Читаются все фильтры таблицы 6, а сверх неё — `BrotliDecode`. Его нет ни в одной части ISO 32000:
это расширение Mozilla, и файл с ним не является соответствующим PDF. Читать его почти ничего не
стоит, а значит такой файл откроется вместо того, чтобы показать пустые страницы; писать его
библиотека не умеет и не будет. Валидатор PDF/A от этого не слабеет: белый список таблицы 6 он
проверяет отдельно.

## Встроенные изображения: где кончаются данные

У конструкции `BI … ID … EI` (§8.9.7) нет длины в синтаксисе потока, и историческая практика —
искать `EI`, стоящий отдельным токеном. Это догадка: сжатые данные вправе содержать эти два байта,
и тогда изображение обрезается посреди себя, а хвост разбирается как операторы.

PDF 2.0 закрыл дыру ключом `L` (сокращение от `Length`), который «shall be present on all inline
images». Читатель верит ему первым: если объявленная длина укладывается в поток и приводит ровно к
`EI`, данные берутся по ней. Не сходится — значит файл уже сломан, и в ход идёт прежняя эвристика,
а не обрезание по числу, которое очевидно врёт. Незакодированное изображение без `L` по-прежнему
измеряется по собственной геометрии.

Отдельная тонкость оттуда же: обычно за `ID` стоит ровно один пробельный символ, но если последний
фильтр цепочки — `ASCIIHexDecode` или `ASCII85Decode`, пробелов может быть сколько угодно, и они не
часть данных.

## Два способа сохранить

**Полная перезапись** собирает файл заново. Объекты, которые модель ни разу не разбирала,
копируются байт в байт; номера объектов сохраняются.

```csharp
document.Save("out.pdf");
document.Save("out.pdf", new PdfSaveOptions { RemoveUnusedObjects = true });   // выбросить мусор
document.Save("out.pdf", new PdfSaveOptions { UseObjectStreams = false });     // классический xref
```

**Инкрементальное сохранение** дописывает изменения в конец, не трогая исходные байты. Это
единственный способ изменить подписанный документ, не сломав подписи, которые в нём уже есть.

```csharp
document.SaveIncremental("out.pdf");
```

Модель отслеживает, что именно поменялось: объекты, созданные через `AddObject`, и те, которые
помечены `MarkChanged`. Свойства страниц и информационного словаря помечают себя сами; после правки
чужого словаря напрямую вызовите `document.MarkChanged(id)`.

Инкрементальное сохранение отказывается работать, если таблицу ссылок исходного файла пришлось
собирать заново: дописанная секция ссылалась бы на то, чему никогда нельзя было доверять.
